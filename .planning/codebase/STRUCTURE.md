## Directory Purposes

**`scripts/`:**
- Purpose: All Python pipeline logic. Five single-responsibility scripts plus one shared utility module.
- Contains: Python 3.9+ scripts, `__pycache__/` (gitignored).
- Key files: `utils.py` (import by all others), `aggregator.py` (main generator), `sheets_sync.py` (exporter).

**`docs/`:**
- Purpose: Jekyll site source. Everything here is either hand-edited or generated by `aggregator.py`, then deployed to GitHub Pages from the `gh-pages` branch.
- Contains: Jekyll config, layouts, includes, YAML data files, generated markdown pages, static assets.
- Key files: `_config.yml`, `_layouts/default.html`, `_data/loe.yml`, `_data/sync_status.yml`.

**`docs/_data/`:**
- Purpose: YAML data files consumed by both Jekyll templates (sidebar sync status) and Python scripts (auto-blocks context, LOE export source).
- Generated: `loe.yml` and `sync_status.yml` are written/updated by Python scripts. `calendar.yml` is hand-edited.
- Committed: Yes — these are the live data state committed on each pipeline run.

**`docs/_projects/`:**
- Purpose: Jekyll collection of per-project pages. One `.md` file per discovered project.
- Generated: Yes — fully generated by `aggregator.generate_project_page()`. Do not hand-edit these files; changes are overwritten on the next pipeline run.
- Committed: Yes.

**`repos/`:**
- Purpose: Runtime workspace for shallow clones of project repos during CI.
- Generated: Yes, by CI steps in `aggregate.yml` and `sync_to_sheets.yml`.
- Committed: No — in `.gitignore`. Only `discovered.txt` persists between local runs.

**`templates/`:**
- Purpose: Seed files to bootstrap new project repos into the dashboard ecosystem.
- Contains: `kanban.md` template (copy to project root) and `notify-kf-cpto.yml` workflow (copy to project's `.github/workflows/`).
- Committed: Yes. These are documentation/onboarding artifacts, not executed in this repo.

**`activity/`:**
- Purpose: Local working notes, per-member activity summaries, org-scan outputs.
- Generated: Partially (org-scan outputs).
- Committed: No — in `.gitignore`.

**`.planning/codebase/`:**
- Purpose: GSD codebase map documents consumed by planning and execution agents.
- Generated: Yes, by `/gsd:map-codebase`.
- Committed: No — in `.gitignore` via `.claude/` exclusion (`.planning/` is separate; check `.gitignore` if committing is desired).

## Key File Locations

**Entry Points:**
- `.github/workflows/aggregate.yml`: Primary CI/CD pipeline trigger and orchestrator.
- `.github/workflows/sync_to_sheets.yml`: Standalone Sheets-only refresh workflow.
- `scripts/aggregator.py`: Python pipeline entry point (`main()` at line 536).
- `scripts/sheets_sync.py`: Sheets export entry point (`main()` at line 387).

**Configuration:**
- `docs/_config.yml`: Jekyll site configuration (collections, baseurl, plugins).
- `requirements.txt`: Python dependency declarations.
- `docs/_data/calendar.yml`: Migration project calendar config — edit to change PW start date, total weeks, sprint length, or phases.

**Core Logic:**
- `scripts/utils.py`: All shared constants (`ORG`, `TASK_STATUSES`, `STATUS_TO_MERMAID`, etc.) and all kanban.md parsers. The single source of truth for field names, status values, and path constants.
- `scripts/auto_blocks.py`: `AUTO_BLOCK_RENDERERS` registry — the only place to register new auto-block types.
- `docs/_data/loe.yml`: Canonical LOE intermediate (contract boundary between aggregator and Sheets exporter).
- `docs/_data/sync_status.yml`: Live pipeline health state — read by Jekyll sidebar template and dashboard index.

**Testing:**
- No test suite present. `validate_auto_blocks.py` serves as the CI-enforced lint check for AUTO marker hygiene.

## Naming Conventions

**Files:**
- Python scripts: `snake_case.py` (e.g., `aggregator.py`, `sheets_sync.py`, `auto_blocks.py`).
- Jekyll pages: `kebab-case.md` (e.g., `unified-kanban.md`, `loe-report.md`, `migration-gantt.md`).
- Project pages: `{RepoName}.md` matching the GitHub repo name exactly (e.g., `AIRise-ai-fabric-inspection.md`, `NuoForm---GTM.md`). Generated by aggregator.
- YAML data files: `snake_case.yml` (e.g., `sync_status.yml`, `loe.yml`, `calendar.yml`).
- Workflow files: `snake_case.yml` (e.g., `aggregate.yml`, `sync_to_sheets.yml`).

**Directories:**
- Jekyll convention: leading underscore for special dirs (`_data/`, `_layouts/`, `_includes/`, `_projects/`).
- Standard Python: `scripts/`, `venv/`, `repos/` (runtime).

**Python identifiers:**
- Functions: `snake_case` (e.g., `generate_unified_kanban`, `parse_kanban_tasks`, `load_loe_from_yaml`).
- Constants: `UPPER_SNAKE_CASE` (e.g., `TASK_STATUSES`, `LOE_DATA_FILE`, `STATUS_FILE`, `ORG`).
- Module-level path constants: `UPPER_SNAKE_CASE` with `Path` type (e.g., `BASE_DIR`, `DOCS_DIR`, `DATA_DIR`).

## Where to Add New Code

**New auto-block renderer (computed section in a prose page):**
1. Implement renderer as `def render_{name}(context: dict) -> str` in `scripts/auto_blocks.py`.
2. Register it in `AUTO_BLOCK_RENDERERS` dict in `scripts/auto_blocks.py:113`.
3. Add `<!-- AUTO:{name} -->` / `<!-- /AUTO:{name} -->` markers to the target page.
4. Declare `auto_blocks: [{name}]` in that page's frontmatter.
5. Add any data the renderer needs to `docs/_data/{something}.yml` (loaded automatically by `load_context()`).

**New generated dashboard view (e.g., new aggregated report):**
1. Add a generator function `generate_{view}(data: dict) -> str` in `scripts/aggregator.py`.
2. Call it in `aggregator.main()` and write output to `DOCS_DIR / "{view}.md"`.
3. Add a navigation link in `docs/_includes/sidebar.html`.

**New project repo into the dashboard:**
1. Copy `templates/kanban.md` to the project repo root. Fill in frontmatter.
2. Copy `templates/.github/workflows/notify-kf-cpto.yml` to the project repo's `.github/workflows/`. Add the `KF_PAT` secret to that repo.
3. The next `discover.py` run will find and include it automatically. No changes needed in kf-cpto.

**New shared utility or constant:**
- Add to `scripts/utils.py`. Import from `aggregator.py`, `sheets_sync.py`, or `discover.py` as needed.

**New Jekyll include component:**
- Add `.html` to `docs/_includes/`. Use `{% include filename.html %}` in layouts or pages.

**New YAML data file for templates:**
- Add `docs/_data/{name}.yml`. Jekyll makes it available as `site.data.{name}`. Python scripts can load it via `auto_blocks.load_context()` as `context['{name}']`.

## Special Directories

**`repos/`:**
- Purpose: Populated at CI runtime with shallow clones; consumed by parsers.
- Generated: Yes, by CI `git clone` steps.
- Committed: No (in `.gitignore`). `repos/discovered.txt` is the only persistent artifact and is committed.

**`docs/_site/`:**
- Purpose: Jekyll local build output.
- Generated: Yes, by `jekyll build` locally.
- Committed: No (in `.gitignore`).

**`venv/`:**
- Purpose: Local Python virtual environment.
- Generated: Yes.
- Committed: No (in `.gitignore`).

**`docs/_projects/`:**
- Purpose: Jekyll collection of per-project pages, fully generated.
- Generated: Yes, overwritten on every aggregator run.
- Committed: Yes — the generated output is committed to master so GitHub Pages can serve it.
