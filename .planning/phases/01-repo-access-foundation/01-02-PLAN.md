<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| skill → remote git (clone) | Cloning a remote pulls untrusted content onto the local machine. Must clone only from the katty-fashion org. |
| repo/branch name → subprocess argv | Repo and branch names flow into a `git` invocation; shell injection risk if interpolated into a shell string. |
| templates/ → cloned repo filesystem | Seeding writes files into sibling checkouts (allowed: these are the skill's own clones under repos-local/). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Tampering / Elevation | `git clone` subprocess | mitigate | Build the clone URL from the hardcoded `KF_ORG="Katty-Fashion"` constant + the curated `TRACKED_REPOS` name only; never from arbitrary input. Use arg-list `subprocess.run`, never `shell=True`. |
| T-02-02 | Spoofing | clone remote source | mitigate | Clone exclusively from `git@github.com:Katty-Fashion/<name>.git`; org segment is a constant, not parameterized. |
| T-02-03 | Tampering (path traversal) | `_seed_markers` / clone target paths | mitigate | Targets are built as `REPOS_LOCAL_DIR / <name>` where `<name>` comes from the curated allowlist (no `..`, no user input); seeding writes only within the cloned repo dir. |
| T-02-04 | Denial of Service | missing repo (tech_brainstorming) | accept | Clone failure is non-fatal by design (`Warning:` + continue); the run completes with the repos that did clone. |
| T-02-SC | Tampering | npm/pip/cargo installs | accept | No package installs (stdlib + existing pyyaml only; RESEARCH "No Package Legitimacy Audit Required"). |
</threat_model>
