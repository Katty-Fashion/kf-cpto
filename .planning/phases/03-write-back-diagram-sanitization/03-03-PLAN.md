<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator → batch confirm | The single y/N gate authorizes all outward-facing pushes at once |
| skill → multiple external repos (batch push) | One run pushes to N tracked repos; partial failure must be recoverable |
| KF_PAT (env) → run() | Token read from environment only when a non-dry push is authorized |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-09 | Elevation of Privilege | unconfirmed / accidental batch push | mitigate | single _confirm_batch gate authorizes all writes once (WB-02); dry_run default-safe; no per-repo prompt that could train click-through; tests assert exactly one prompt |
| T-03-10 | Repudiation | no record of what was pushed in a partial-failure batch | mitigate | per-run JSON recovery manifest records every repo's outcome + pushed sha + error (WB-05); enables recovery/audit |
| T-03-11 | Information Disclosure | manifest (containing repo names, shas) committed into kf-cpto | mitigate | MANIFESTS_DIR gitignored (Plan 01); test asserts git check-ignore; no token stored in manifest |
| T-03-12 | Information Disclosure | KF_PAT read at import time leaking into stack traces / logs | mitigate | KF_PAT read from os.environ only inside run() at push time, fail-fast [ERROR] if unset; never logged; dry-run never reads it |
| T-03-13 | Denial of Service | one repo's failure aborting the whole batch | mitigate | _write_repo never raises; run() loop continues past conflict/failure; already-pushed repos' dispatches fire normally |
</threat_model>
