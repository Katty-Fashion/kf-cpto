<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub API → reconcile.py | PR titles/bodies and issue titles are untrusted text flowing into matching + terminal output |
| env (KF_PAT) → reconcile.py → GitHub API | Secret token crosses from environment into an outbound HTTP Authorization header |
| reconcile.py → git subprocess | merge_commit_sha + branch name cross into a `git merge-base` subprocess |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-05 | Information Disclosure | KF_PAT token handling | mitigate | Token read from env only; placed in Authorization header; NEVER printed/logged — log only presence/absence via `Warning:`; acceptance criterion greps that no `print` references `token` |
| T-02-06 | Tampering | crafted PR title/body/issue title flowing into matching | mitigate | Matched only via `task_matches_signal` token normalization (plaintext, no eval/exec); rendered as plain `print()` data |
| T-02-07 | Tampering | `merge_commit_sha` arg to `git merge-base` | mitigate | Passed through arg-list `_run_git` (never shell-interpolated); falsy sha is skipped before the git call (Pitfall 1) |
| T-02-08 | Spoofing/Tampering | reverted or unreachable merge falsely signalling Done | mitigate | `git merge-base --is-ancestor` reachability gate is the canonical revert detector; reachable != True is skipped (RECON-08) — no commit-message `Revert "..."` parsing |
| T-02-09 | Denial of Service | GitHub API rate limit exhaustion | accept | `[WARN]` when X-RateLimit-Remaining < 100; unauthenticated runs degrade to empty Tier-1 proposals rather than failing the pipeline |
| T-02-SC | Tampering | npm/pip/cargo installs | accept | No new packages installed (RESEARCH Package Legitimacy Audit: zero installs; `requests` already pinned in requirements.txt) |
</threat_model>
