# Plan: Enhance OKF Knowledge-Graph Visualizer with fcose Compound Layout

## Objective

Upgrade the OKF knowledge-graph page (`docs/okf-graph.md`) from a flat breadthfirst
layout to a fcose compound (nested) layout where project nodes become parent containers
holding their task children. Add a viz-type selector and repulsion/nesting sliders.

## Context

- `docs/okf-graph.md` — existing 297-line Cytoscape visualizer (extend, do not rewrite)
- `scripts/okf_export.py` — `emit_okf_graph_json()` at line 696 builds the graph JSON
- `docs/_data/okf_graph.json` — current graph output (no `parent` field on task nodes)
- `docs/_layouts/default.html` — CDN script loading pattern to mirror

## Tasks

### Task 1 — Add `parent` field to task nodes in `emit_okf_graph_json`

**File:** `scripts/okf_export.py` (lines 758–778)

Inside the task-node loop, add `"parent": proj_id` to every Task node dict. Projects,
Metrics, and Milestones get no `parent` key. Keep `contains` edges unchanged in JSON.
Keep output sorted/deterministic.

### Task 2 — Enhance `docs/okf-graph.md` with fcose compound layout + controls

**Files:** `docs/okf-graph.md`, `docs/_data/okf_graph.json` (regenerated)

Changes to okf-graph.md:
1. Add three CDN UMD scripts (layout-base, cose-base, cytoscape-fcose) BEFORE the
   existing inline `<script>` block, mirroring the cytoscape.umd.js pattern.
2. In the element-building loop, pass `data.parent` from node's `parent` field to
   make task nodes children of their project compound node.
3. Skip `kind === "contains"` edges when building elements (nesting replaces them).
4. Add compound node styles: translucent background, text-valign top, padding 12px,
   rounded, distinct border.
5. Change default layout to fcose with nodeRepulsion=4500, nestingFactor=0.1.
6. Add control bar: layout selector, repulsion slider, nesting slider, re-run button.
7. Preserve all existing features (search, type-filter, click-info).
8. Re-run `python scripts/aggregator.py` to regenerate okf_graph.json with parent fields.
